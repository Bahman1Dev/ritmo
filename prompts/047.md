## ۰ — قوانین اجرا (پیش از نوشتن اولین خط کد بخوان)

### ۰.۱ محدودهٔ ممنوعه (Hard Out of Scope)

- ⛔ **`lib/features/today/presentation/home_navigation_shell.dart`**: ساختار، تعداد و ترتیب تب‌ها، رفتار انتخاب، انیمیشن ورود و خروج، و چیدمان دکمهٔ مرکزی **مطلقاً تغییر نمی‌کند**. تنها مجوز تو در این فایل، جایگزینی مقادیر رنگ هاردکد با توکن معادل است، به شرطی که رنگ نهایی رندرشده در پالت پیش‌فرض با قبل **یکسان یا تفکیک‌ناپذیر با چشم** باشد.
- ⛔ هیچ تغییری در منطق دامنه، کوئری‌ها، اسکیمای دیتابیس، مهاجرت‌های موجود، سرویس‌های نوتیفیکیشن و آلارم، و موتورهای محاسباتی. این پرامپت **صرفاً لایهٔ `presentation` و `core/theme` و `core/ux` و `core/widgets`** را دست می‌زند.
- ⛔ افزودن پکیج جدید به `pubspec.yaml` ممنوع است، مگر با طی کردن مسیر بخش ۰.۷.
- ⛔ حذف یا تغییر نام هیچ فایل موجودی بدون ذکر صریح در فهرست کامیت‌های بخش ۱۵ ممنوع است.
- ⛔ **Color Picker آزاد** برای کاربر در این نسخه پیاده نمی‌شود. فقط انتخاب از میان ۵ پالت از‌پیش‌طراحی‌شده.
- ⛔ تغییر متن‌های محصولی (کپی‌رایتینگ) موجود، جز در مواردی که این پرامپت متن دقیق را داده است.
- ⛔ قفل پرمیوم روی پالت‌ها و تاریک‌شدن خودکار بر اساس اوقات شرعی، **در این پرامپت پیاده نمی‌شود**. صرفاً نقاط اتصال (hook) آن‌ها را طبق فاز ۶ آماده می‌گذاری.

### ۰.۲ اصل «اول تحقیق، بعد تغییر» (Verify-First)

این پرامپت بر پایهٔ بازخوانی مخزن نوشته شده، اما ممکن است بعضی جزئیات از زمان نگارش جابه‌جا شده باشد. پس **هر جا این پرامپت مسیر فایل، نام کلاس، نام متد یا مقدار رنگی را ذکر می‌کند، پیش از تغییر آن را با `grep` تأیید کن.**

- اگر مسیر یا نام دقیقاً همان بود: طبق پرامپت عمل کن.
- اگر جابه‌جا شده بود: معادل واقعی را پیدا کن، همان را تغییر بده، و در گزارش نهایی زیر عنوان «انحراف از پرامپت» ثبت کن.
- اگر چیزی که پرامپت می‌گوید «وجود دارد» را پیدا نکردی: آن را **نساز** و **حدس نزن**؛ در گزارش بنویس «یافت نشد» و برو سراغ آیتم بعدی.
- ⚠️ هیچ‌گاه یک فایل را «کورکورانه» بازنویسی نکن. الگوی کار: `grep` ← خواندن فایل ← تغییر حداقلی هدفمند.

### ۰.۵ نام‌گذاری و سبک کد

## ۲ — جهت بصری تأییدشده: «یشم شب»

### ۲.۱ بیانیهٔ طراحی

> زغالی آرام · یشمی عمیق · سطوح تمیز · طلایی شامپاینی بسیار محدود · تایپوگرافی فارسی قوی · شیشه فقط در نقاط کلیدی
> 

Ritmo یک اپ «آرامش و انسجام» است، نه یک اپ «هیجان». پس مدرن‌بودن را از راه **نظم، فاصله‌گذاری سخاوتمندانه و تایپوگرافی خوب** می‌گیریم، نه از راه گرادیان‌های پرسروصدا و بلور همه‌جایی.

### ۲.۲ قوانین رنگ معنایی (غیرقابل نقض)

| رنگ | تنها کاربرد مجاز |
| --- | --- |
| **Primary (یشمی در پالت پیش‌فرض)** | دکمهٔ اصلی · تب فعال · حالت انتخاب‌شده · حلقهٔ فوکوس · لینک |
| **Accent (طلایی شامپاینی)** | دستاورد · نشان Premium · رکورد شخصی · لحظهٔ ویژه. حداکثر **یک** نقطه در هر صفحه |
| **Success (سبز)** | فقط تیک و تکمیل شدن |
| **Warning (کهربایی)** | فقط هشدار قابل جبران |
| **Error (قرمز)** | فقط خطا، خطر، و دارو |
| **رنگ هویتی مادول** | فقط آیکن مادول، نوار باریک کنار کارت، رنگ نمودار، و Hero همان مادول |

معنی عملی: رنگ هویتی مادول **هیچ‌وقت** پس‌زمینهٔ دکمهٔ اصلی نمی‌شود، و Primary **هیچ‌وقت** برای دسته‌بندی به کار نمی‌رود.

### ۲.۳ چیزهایی که عمداً نمی‌خواهیم

- گلس‌مورفیزم روی هر کارت. شیشه گران است و اگر همه‌جا باشد بی‌معنا می‌شود.
- بیش از یک گرادیان برند در کل اپ.
- سایه‌های سنگین و چندلایه.
- بیش از سه وزن فونت.
- رنگ‌های اشباع‌شدهٔ نئونی روی پس‌زمینهٔ روشن.

این بخش صرفاً چارچوب است؛ مقادیر دقیق در بخش‌های ۳ تا ۵ آمده و در فاز ۱ پیاده می‌شود.

## ۳ — سیستم توکن مرکزی (مرجع دقیق فاز ۱)

### ۳.۱ ساختار کلاس‌ها

فایل جدید `lib/core/theme/ritmo_colors.dart`:

```dart
// مجموعهٔ کامل توکن‌های رنگ برای یک حالت (روشن یا تاریک) از یک پالت.
// جایگزین همهٔ رنگ‌های هاردکد لایهٔ presentation می‌شود.
@immutable
class RitmoColors {
  const RitmoColors({
    required this.background,
    required this.surface,
    required this.surfaceElevated,
    required this.surfaceSunken,
    required this.primary,
    required this.primaryPressed,
    required this.primaryContainer,
    required this.onPrimary,
    required this.accent,
    required this.accentContainer,
    required this.success,
    required this.warning,
    required this.error,
    required this.textPrimary,
    required this.textSecondary,
    required this.textTertiary,
    required this.textOnColor,
    required this.border,
    required this.divider,
    required this.disabled,
    required this.overlay,
    required this.glassTint,
    required this.shadow,
    required this.systemNavBar,
    required this.brandGradient,
    required this.modules,
  });

  final Color background;        // پس‌زمینهٔ Scaffold
  final Color surface;           // کارت معمولی
  final Color surfaceElevated;   // کارت برجسته و شیت
  final Color surfaceSunken;     // فیلد ورودی، ترک نوار پیشرفت
  final Color primary;
  final Color primaryPressed;
  final Color primaryContainer;  // پس‌زمینهٔ ملایم حالت انتخاب‌شده
  final Color onPrimary;         // متن و آیکن روی primary
  final Color accent;            // طلایی شامپاینی
  final Color accentContainer;
  final Color success;
  final Color warning;
  final Color error;
  final Color textPrimary;
  final Color textSecondary;
  final Color textTertiary;      // متن کم‌اهمیت، placeholder
  final Color textOnColor;       // متن روی success/warning/error
  final Color border;            // خط دور کارت (فقط حالت تاریک فعال است)
  final Color divider;
  final Color disabled;
  final Color overlay;           // پشت شیت و دیالوگ
  final Color glassTint;         // رنگ روی BackdropFilter
  final Color shadow;            // سایه (فقط حالت روشن فعال است)
  final Color systemNavBar;      // رنگ نوار ناوبری سیستم
  final List<Color> brandGradient; // دقیقاً دو رنگ
  final RitmoModuleColors modules;

  RitmoColors copyWith({ /* همهٔ فیلدها اختیاری */ });
  static RitmoColors lerp(RitmoColors a, RitmoColors b, double t);
}
```

قواعد اجباری این کلاس:

- `RitmoColors` باید `ThemeExtension<RitmoColors>` را پیاده کند تا `lerp` در تعویض تم کار کند و انتقال نرم باشد.
- `extension RitmoThemeExtension on BuildContext { RitmoColors get colors }` موجود است و باید **از `Theme.of(context).extension<RitmoColors>()!` بخواند**، نه از `static const`. این تنها راه دینامیک شدن پالت است.
- هر `Color` باید `const` باشد و با `Color(0xAARRGGBB)` نوشته شود.
- ⛔ در هیچ ویجتی `Colors.white` / `Colors.black` / `Colors.grey` استفاده نمی‌شود. معادل توکنی‌شان را بگیر.
- ⛔ `withOpacity` را با `withValues(alpha: ...)` جایگزین کن (API جدید Flutter).

| `display` | ۳۲ | Bold | ۱٫۳ | عدد بزرگ Hero، شمارندهٔ تایمر |
| `headline` | ۲۴ | Bold | ۱٫۴ | عنوان صفحه |
| `titleLarge` | ۱۸ | Bold | ۱٫۵ | عنوان بخش |
| `titleMedium` | ۱۶ | Medium | ۱٫۵ | عنوان کارت |
| `bodyLarge` | ۱۵ | Regular | ۱٫۷ | متن اصلی |
| `bodyMedium` | ۱۳ | Regular | ۱٫۷ | متن ثانویه و توضیح |
| `labelLarge` | ۱۴ | Medium | ۱٫۴ | متن دکمه و تب |
| `labelSmall` | ۱۱ | Medium | ۱٫۴ | چیپ، برچسب، واحد |

قواعد اجباری تایپوگرافی:

- `fontFamily: 'Vazirmatn'` **فقط یک بار** و فقط در `ThemeData.textTheme` و `ThemeData.fontFamily` نوشته می‌شود. هر `fontFamily` دیگری در لایهٔ `presentation/` حذف می‌شود.
- حداکثر سه وزن: `w400` Regular، `w500` Medium، `w700` Bold. `w600` و `w800` و `w300` ممنوع.
- ارتفاع خط فارسی سخاوتمندانه است (`height` بالای ۱٫۴) چون کشیدگی و اعراب فارسی به فضای عمودی بیشتری نیاز دارد.
- اعداد مهم (تایمر، درصد پیشرفت، شمارنده) باید `fontFeatures: [FontFeature.tabularFigures()]` داشته باشند تا با تغییر عدد، عرض نپرد.
- همهٔ ارقام نمایشی فارسی هستند؛ اگر تابع کمکی تبدیل رقم موجود است همان را استفاده کن و تابع دوم نساز.
- `letterSpacing` برای فارسی صفر است. هر `letterSpacing` غیرصفر روی متن فارسی حذف می‌شود.

### ۳.۸ هپتیک — یک قرارداد واحد

```dart

### ۳.۹ گرادیان و Glow

- در کل اپ فقط **یک** گرادیان برند وجود دارد: `colors.brandGradient` با دقیقاً دو رنگ.
- حداکثر **یک** نقطهٔ Glow در هر صفحه. Glow با `colors.primary.withValues(alpha: 0.18)` و `blurRadius: 48` ساخته می‌شود.
- `timeAwareGradient(brightness)` موجود حفظ می‌شود اما رنگ‌هایش از پالت فعال می‌آید، نه از ثابت‌های هاردکد.

## ۵ — چرخهٔ ۸ رنگهٔ هارمونیک مادول‌ها

### ۵.۱ ایده

هر پالت **چرخهٔ ۸ رنگهٔ مستقل خودش** را دارد. نگاشت «اسلات ← مادول» ثابت است و هرگز تغییر نمی‌کند؛ اما مقدار رنگ هر اسلات از پالت فعال می‌آید. نتیجه: کاربر پالت را عوض می‌کند، هویت رنگی مادول‌ها حفظ می‌شود ولی همه در یک خانوادهٔ رنگی هماهنگ می‌نشینند.

- پس‌زمینهٔ ملایم هر مادول **ذخیره نمی‌شود** و محاسبه‌ای است: در روشن `moduleColor.withValues(alpha: 0.10)` و در تاریک `withValues(alpha: 0.16)`. توکن جدید نساز.
- رنگ مادول هرگز برای متن روی پس‌زمینهٔ خودش استفاده نمی‌شود؛ متن همیشه `textPrimary` است.
- ⛔ رنگ مادول هرگز پس‌زمینهٔ دکمهٔ اصلی، تب فعال، یا تیک تکمیل نمی‌شود.

### ۵.۴ فرمول تولید چرخه (برای مستندسازی و بازتولید)

```

حالت تاریک : اشباع ۴۵ تا ۵۸ درصد ، روشنایی ۶۰ تا ۶۸ درصد
محدودهٔ ممنوع: هیچ رنگ مادولی در بازهٔ فام ۳۴۸° تا ۱۲° نمی‌نشیند (رزرو خطا)

مقادیر نهایی زیر از همین فرمول به دست آمده‌اند و **همان‌ها را استفاده کن**؛ دوباره محاسبه نکن.

### گام ۱.۲ — `RitmoTheme.build`

در `lib/core/theme/ritmo_theme.dart`:

```dart
class RitmoTheme {
  static ThemeData build({
    required RitmoPalette palette,
    required Brightness brightness,
    bool reduceTransparency = false,
    bool trueBlack = false,
  }) {
    var colors = palette.forBrightness(brightness);
    if (trueBlack && brightness == Brightness.dark) {
      colors = colors.copyWith(
        background: const Color(0xFF000000),
        systemNavBar: const Color(0xFF000000),
      );
    }
    return ThemeData(
      useMaterial3: true,
      brightness: brightness,
      fontFamily: 'Vazirmatn',
      scaffoldBackgroundColor: colors.background,
      colorScheme: _schemeFrom(colors, brightness),
      textTheme: RitmoTypography.textTheme(colors),
      extensions: <ThemeExtension<dynamic>>[
        colors,
        RitmoBehavior(reduceTransparency: reduceTransparency),
      ],
      // … cardTheme, inputDecorationTheme, dividerTheme, chipTheme,
      //     bottomSheetTheme, snackBarTheme, tabBarTheme, iconTheme
      //     همه از colors تغذیه می‌شوند
    );
  }
}
```

الزامات این گام:

1. `_schemeFrom` باید **همهٔ** فیلدهای `ColorScheme` را پر کند (`primary`، `onPrimary`، `secondary`، `surface`، `onSurface`، `error`، `outline`، `surfaceContainerHighest` و بقیه). دلیل: هر ویجت Material که مستقیماً توکن نمی‌خواند باید خودبه‌خود درست دربیاید.
2. `lightTheme` و `darkTheme` موجود **حذف نمی‌شوند** بلکه به `build(palette: RitmoPalette.jadeNoir, ...)` تبدیل و `@Deprecated('از RitmoTheme.build استفاده کن')` می‌شوند، تا مهاجرت تدریجی ممکن باشد.
3. ثابت‌های `RitmoTheme.primaryBg = Color(0xFF0F172A)` و `RitmoTheme.accent = Color(0xFF38BDF8)` **حذف** می‌شوند. قبل از حذف، `grep` بزن و هر مصرف‌کننده را به `context.colors` وصل کن.
4. خطای موجود در `tool/analyze_output.txt` که می‌گوید `The getter 'primaryColor' isn't defined for the type 'RitmoTheme'` در `unified_assistant_sheet.dart` حدود خط `283`، در همین گام با `context.colors.primary` حل می‌شود.
5. `inputDecoration()` و `buildBackgroundContainer()` و `glassCard()` و `glassCardLight()` موجود حفظ می‌شوند ولی امضایشان `BuildContext` می‌گیرد تا رنگ را از تم فعال بخوانند.

</aside>

### گام ۶.۱ — تست کنتراست خودکار

فایل `test/theme/contrast_test.dart`. ماتریس: **پنج پالت × دو حالت = ده مجموعهٔ رنگ**. برای هر ده مجموعه این ۷ شرط باید برقرار باشد:

| # | جفت رنگ | حداقل نسبت |
| --- | --- | --- |
| ۱ | `textPrimary` روی `surface` | `4.5:1` |
| ۲ | `textPrimary` روی `background` | `4.5:1` |
| ۳ | `onPrimary` روی `primary` | `4.5:1` |
| ۴ | `textSecondary` روی `surface` | `3:1` |
| ۵ | `textOnColor` روی `error` و `success` و `warning` | `4.5:1` |
| ۶ | `primary` روی `surface` (متن لینک) | `3:1` |
| ۷ | هر ۸ رنگ مادول روی `surface` | `3:1` |

قواعد:

- محاسبهٔ نسبت طبق فرمول روشنایی نسبی WCAG باشد، در یک تابع کمکی داخل خود تست.
- پیام خطای تست باید **نام پالت، نام حالت، نام دو توکن و نسبت محاسبه‌شده** را بدهد؛ وگرنه دیباگ لایه به لایه خواهد بود.
- اگر یک جفت رنگ رد شد، **مقدار رنگ را حداقل تغییر بده تا پاس شود** و در گزارش مقدار قدیم و جدید را بنویس. تست را ضعیف نکن.
- پالت گرافیت بیشترین ریسک را دارد؛ اول از همه آن را بررسی کن.

### گام ۶.۲ — احترام به تنظیمات دسترسی‌پذیری سیستم

| تنطیم سیستم | رفتار اجباری اپ | محل پیاده‌سازی |
| --- | --- | --- |
| `MediaQuery.highContrast` | بلور حذف، خط دور کارت‌ها پررنگ‌تر، `textTertiary` به `textSecondary` ارتقا | `RitmoGlassSurface` و `RitmoCard` |
| `MediaQuery.disableAnimations` | همهٔ `Duration` ها صفر، شامل `themeSwap` | تابع کمکی در `RitmoMotion` |

| `theme_reduce_transparency` | بلور کاملاً حذف و `surfaceElevated` مات | `RitmoGlassSurface` |
| `theme_true_black` | `background` و `systemNavBar` مشکی مطلق، فقط در حالت تاریک | `RitmoTheme.build` |

⚠️ در حالت مشکی مطلق، `surface` را **مشکی نکن**. اگر هم پس‌زمینه و هم کارت مشکی باشند، مرز کارت‌ها ناپدید می‌شود. فقط `background` و `systemNavBar` تغییر می‌کنند.

### گام ۶.۳ — سطوح بیرون از دسترس `Theme`

این سه جا به `BuildContext` دسترسی ندارند و اگر نادیده بگیری، کاربر متوجه ناهماهنگی می‌شود:

1. **ویجت اندروید** (`RitmoAgendaWidgetProvider.kt` و `RitmoWidgetFactory.kt`) — رنگ تأکیدی ویجت باید از پالت فعال بیاید. روش: هر بار که پالت عوض می‌شود، دو رشتهٔ hex (`primary` و `background`) را در همان محلی که ویجت می‌خواند بنویس و سپس به‌روزرسانی ویجت را تریگر کن. تابع `parseColor(hex, fallback)` موجود است و باید از همان استفاده کنی.
2. **رنگ تأکیدی نوتیفیکیشن** — همان منطق. اگر دسترسی به پالت در لایهٔ سرویس ممکن نبود، رنگ پالت پیش‌فرض را بگذار و در گزارش بنویس.
3. **اسپلش نیتیو** — طبق گام ۵٫۴ خنثی می‌ماند.

⚠️ اگر به‌روزرسانی ویجت پیچیده شد یا نیاز به تغییر منطق داشت، **انجامش نده**. فقط در گزارش بنویس که ویجت فعلاً پالت پیش‌فرض را نشان می‌دهد. منطق ویجت خارج از محدودهٔ این پرامپت است.

## ۱۴ — کنترل کیفیت

در پایان هر فاز و پیش از هر کامیت، به همین ترتیب:

```bash
flutter pub get
flutter analyze --fatal-warnings .
flutter test
dart format <فایل‌های تغییریافته>
git status --short
git diff --check
git diff --stat
```

قواعد:

- `flutter analyze --fatal-warnings .` باید **کاملاً پاک** باشد. خطای موجود `primaryColor` هم در فاز ۱ رفع می‌شود.
- `dart format` فقط روی فایل‌های تغییریافته، نه کل پروژه (دیف غیرقابل بازبینی می‌شود).
- `git status --short` باید فقط فایل‌های مورد انتظار را نشان دهد. هر فایل غیرمنتظره را بررسی کن.
- هیچ کامیتی با تست قرمز زده نمی‌شود.

## ۱۶ — Definition of Done

تسک فقط وقتی تمام است که هر ۱۶ مورد زیر برقرار باشد:

1. هر شش فاز انجام شده و دروازهٔ هر فاز سبز است.
2. `flutter analyze --fatal-warnings .` کاملاً پاک است.
3. `flutter test` کاملاً سبز است، شامل ۳۰ Golden و هفت گارد.
4. کاربر می‌تواند از تنظیمات، پالت را از میان پنج گزینه عوض کند و اثر فوری ببیند.
5. حالت روشنایی و پالت دو انتخاب کاملاً مستقل‌اند (۱۵ ترکیب).
6. هر پنج پالت در هر دو حالت روشنایی تست کنتراست را پاس می‌کنند.
7. شمارندهٔ رنگ هاردکد در `lib/features/` صفر است.
8. در کل کد مشترک فقط یک پیاده‌سازی گلس وجود دارد.
9. `supplementary_sports_theme.dart` حذف شده و `calendar_tokens.dart` فقط لایهٔ نگاشت است.
10. ناوبری سراسری از نظر رفتار و ساختار دست‌نخورده مانده است.
11. لوگو و Orb با تغییر پالت عوض نمی‌شوند.
12. مقدار نامعتبر یا غایب در تنظیمات تم، هرگز کرش نمی‌دهد.
13. `docs/RITMO_DESIGN_TOKENS.md` و `docs/theme_migration.md` و `docs/theme_baseline/` موجودند.
14. `prompts/047_REPORT.md` طبق قالب بخش ۱۷ نوشته شده.
15. همهٔ سناریوهای S1 تا S33 با نتیجهٔ ثبت‌شده.
16. هیچ پکیج جدیدی به `pubspec.yaml` اضافه نشده است.
17. هیچ تغییری در منطق دامنه، دیتابیس، مهاجرت‌ها و سرویس‌های نوتیفیکیشن رخ نداده است.
