## قواعد حاکم بر کل این پرامپت

۱. **یک کامیت برای هر واحد کاری.** `git add .` ممنوع. فقط فایل‌های همان واحد کاری را stage کن.

۲. **هرگز «سبز شد» ننویس بدون خروجی خام.** هر ادعای موفقیت باید با یک فایل کامیت‌شده در `tool/` همراه باشد که خروجی دقیق دستور را دارد. آن فایل را **کامل بخوان** و تعداد error / warning / info را در گزارش بنویس.

۳. **دستور آنالیز دقیقاً همان دستور CI است:** `flutter analyze --fatal-warnings .` — نه `flutter analyze lib/`.

۴. **قبل از اینکه بگویی چیزی «وصل شد»، ثابت کن فراخوانی می‌شود** — با یک تست، یا با نشان دادن خط ثبت‌کننده.

۵. **حدس زدن ممنوع.** اگر برای رفع خطای کامپایل مجبور شدی یک مقدار enum یا نام متد را عوض کنی، اول بگو آن شاخه برای چه بوده و بعد تغییر بده.

۶. در هر **نقطهٔ توقف** بایست، گزارش بده، منتظر تأیید بمان.

# فاز ۲ — باس فرمان

## چرا

هدف محصولی این است: **هر کاری که کاربر در اپ می‌تواند انجام دهد، دستیار هم بتواند.** معماری فعلی این را ساختاراً غیرممکن کرده. `AssistantActionType` دقیقاً ۲۴ مقدار دارد و هر قابلیت جدید یعنی یک مقدار enum + یک `case` در `label` + یک `case` در `icon` + یک `case` در سوئیچ ۹۰۰ خطی. اپ صدها عمل دارد و دستیار ۲۴ تا.

راه‌حل: **یک مسیر نوشتن، دو جبههٔ ورودی.**

```
کاربر (UI)              دستیار (AI)
     │                       │
     └───────┬───────────────┘
             ▼
      RitmoCommandBus
اعتبارسنجی ← مجوز ← تراکنش ← رویداد ← ممیزی
             ▼
      دیتابیس / موتورها
```

## WU-2.1 — تعریف `RitmoCommand`

پروژه از قبل `CompletionRequest` را به‌صورت `sealed class` با ۱۳ فرزند دارد. همان الگو را تعمیم بده:

```dart
sealed class RitmoCommand {
  String get id;                        // 'routine.complete'
  String get humanTitle;                // 'تیک زدن روتین'
  Sensitivity get sensitivity;
  Set<DataDomain> get touches;
  Map<String, ParamSpec> get schema;    // برای تولید خودکار مانیفست

  Future<CommandResult> run(CommandContext ctx);
  RitmoCommand? inverse(CommandResult result);   // برای undo
}
```

- [ ]  `ParamSpec` باید نوع، اجباری بودن، بازهٔ مجاز و توضیح فارسی داشته باشد.
- [ ]  `CommandContext` باید `DatabaseExecutor` تراکنشی، ساعت، و منبع فراخوانی (`user` یا `assistant`) را حمل کند.

## WU-2.2 — باس

```dart
class RitmoCommandBus {
```

۴. انتشار رویدادها **بعد از** commit موفق، نه وسط تراکنش

۵. نوشتن در `assistant_audit_log` شامل فرمان معکوس

- [ ]  قاعدهٔ سخت: **هیچ نوشتنی خارج از باس مجاز نیست** — نه در UI، نه در دستیار.

## WU-2.3 — مهاجرت ۲۴ اکشن موجود

- [ ]  هر ۲۴ مقدار `AssistantActionType` را به یک `RitmoCommand` تبدیل کن.

# فاز ۴ — لایهٔ خواندن

## چرا نه دسترسی خام

خواستهٔ اصلی این بود که دستیار «به دیتابیس و فایل‌ها دسترسی کامل داشته باشد تا مسیر انجام هر کاری را پیدا کند». دسترسی خام SQL به اسکیمای نسخهٔ ۵۹ که دادهٔ سیکل و سلامت و بازتاب دارد، هم خطر حریم خصوصی است هم غیرقابل تست هم توکن‌سوز. دسترسی به سورس کد هم کمکی نمی‌کند — مدل با خواندن یک فایل ۹۰۰ خطی کاری نمی‌تواند بکند که با یک مانیفست خوب نتواند.

راه درست: **نماهای پاک‌سازی‌شده با `SELECT` آزاد روی آن‌ها.**

```sql
CREATE VIEW ai_v_completion_stats AS
```
