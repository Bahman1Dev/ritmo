## ۰. قرارداد اجرا

۱. فایل پرامپت: `prompts/056.md` — گزارش الزامی: `prompts/056_REPORT.md`.

### ۲.۲ نقطهٔ ورود واحد

فایل جدید `lib/features/study/study_module_entry.dart`:

```dart
/// تنها راهِ باز کردن ماژول درس در کل اپ.
/// هیچ فایل دیگری حق ندارد مستقیماً StudyHomeScreen یا KonkurScreen را push کند.
class StudyModuleEntry {
  const StudyModuleEntry._();

  static Future<void> open(BuildContext context, {StudyDeepLink? link}) async {
    final settings = await StudySettingsRepository.instance.load();

    if (!settings.moduleEnabled) {
      await StudyActivationSheet.show(context);
      return;
    }

    // تصمیمِ حالت، قبل از push. دقیقاً یک شرط، دقیقاً یک کلید.
    final Widget root = settings.konkurMode
        ? const KonkurScreen()
        : const StudyHomeScreen();

    if (!context.mounted) return;
    await Navigator.push(
      context,
      MaterialPageRoute(
        builder: (_) => root,
        settings: const RouteSettings(name: '/study'),
      ),
    );
  }

  /// تعویض حالت: کلید را می‌نویسد، صفحهٔ فعلی را می‌بندد و ریشه را دوباره می‌سازد.
  static Future<void> switchMode(
    BuildContext context, {
    required bool konkur,
  }) async {
    await StudySettingsRepository.instance.setKonkurMode(konkur);
    if (!context.mounted) return;
    Navigator.of(context).pop();
    await open(context);
  }
}
```

- [ ]  `StudySettingsRepository.load()` فقط و فقط `study_konkur_mode` را برای تعیین حالت می‌خواند. **هیچ شرط یا/OR با هیچ کلید دیگری مجاز نیست.** اگر در گرِپ نهایی حتی یک `module_konkur_enabled` در `lib/` باقی مانده باشد، این فاز رد است.
- [ ]  نوشتن تنظیمات فقط از طریق repository با `ConflictAlgorithm.replace`.

### ۱.۱ مهاجرت

یک کلاس مهاجرت جدید بعد از `MigrationV59` اضافه کن. کارهایش دقیقاً این‌هاست:

```sql
-- تفکیک دادهٔ کاربر از پریست کنکور

safeAddColumn: konkur_subjects.emoji         TEXT
safeAddColumn: konkur_subjects.weeklyTargetMinutes INTEGER NOT NULL DEFAULT 0
safeAddColumn: konkur_topics.origin          TEXT NOT NULL DEFAULT 'USER'

-- جلسهٔ مطالعهٔ صادقانه
safeAddColumn: konkur_study_sessions.startedAtMs INTEGER
safeAddColumn: konkur_study_sessions.endedAtMs   INTEGER
safeAddColumn: konkur_study_sessions.source      TEXT NOT NULL DEFAULT 'MANUAL'  -- TIMER | MANUAL
safeAddColumn: konkur_study_sessions.quality     INTEGER                          -- 1..3، اختیاری
```

```sql
CREATE TABLE IF NOT EXISTS study_active_session (
  id TEXT PRIMARY KEY CHECK (id = 'singleton'),
  subjectId TEXT,
  topicId TEXT,
  mode TEXT NOT NULL DEFAULT 'LEARN',        -- LEARN | PRACTICE | REVIEW

```

```sql
-- برچسب‌گذاری گذشته
UPDATE konkur_subjects SET origin = 'KONKUR_PRESET' WHERE isPreset = 1;
UPDATE konkur_topics   SET origin = 'KONKUR_PRESET'
  WHERE subjectId IN (SELECT id FROM konkur_subjects WHERE isPreset = 1);

-- انتقال حالت کاربران فعلی، بعد کشتن کلید قدیمی
INSERT OR REPLACE INTO app_settings (key, value, updatedAt)
SELECT 'study_konkur_mode', 'true', CAST(strftime('%s','now') AS INTEGER) * 1000
WHERE EXISTS (
  SELECT 1 FROM app_settings WHERE key = 'module_konkur_enabled' AND value = 'true'
);

INSERT OR REPLACE INTO app_settings (key, value, updatedAt)
SELECT 'study_konkur_setup_done', value, CAST(strftime('%s','now') AS INTEGER) * 1000
FROM app_settings WHERE key = 'konkur_setup_done';

DELETE FROM app_settings WHERE key = 'module_konkur_enabled';
```

## فاز ۳ — صفحهٔ درس: طراحی کامل

<aside>
🎯

**فلسفهٔ صفحه**

کاربر وقتی این صفحه را باز می‌کند یک سؤال دارد: «الان چی بخونم و چطور شروع کنم؟»

صفحه باید در **دو ثانیه** جواب بدهد و در **یک لمس** جلسه را شروع کند. هر چیزی که این مسیر را کند کند، حذف است.
