```
## بخش ۲ — تصمیم معماری (این را تغییر نده)

**منبع حقیقتِ «انجام شد» برای عبادات، از این پس جدول لاگ تاریخ‌دار
`worship_completions` است.** ستون‌های `dailyDone` / `dailyDoneDate` روی
`worship_practices` **حذف نمی‌شوند** (سازگاری عقب‌رو + شمارندهٔ ذکر) بلکه به
**کش مشتق‌شده** تبدیل می‌شوند که در همان تراکنش هم‌زمان به‌روز می‌شود.

قاعده: **هر خواندنِ وضعیت یک تاریخ، از `worship_completions` است. هیچ خواننده‌ای
دیگر `dailyDone` را برای تعیین وضعیتِ یک تاریخ نمی‌خواند.**

استثنا: `dailyDone` برای دامنه‌های شمارشی (`QURAN` / `DHIKR`) همچنان شمارندهٔ
پیشرفت روزانه است (`dailyDone / dailyTarget`)، ولی «تکمیل روز» از
`worship_completions` خوانده می‌شود.
```

CREATE TABLE IF NOT EXISTS worship_completions (

id TEXT PRIMARY KEY,

practiceId TEXT NOT NULL,

dateStr TEXT NOT NULL,

practiceType TEXT NOT NULL,       -- PRAYER|MUSTAHAB|QURAN|DHIKR|FASTING

resultType TEXT NOT NULL,         -- DONE|SKIPPED|PARTIAL|QADA_ADDED

countDone INTEGER NOT NULL DEFAULT 1,

countTarget INTEGER,

reason TEXT,

loggedAt INTEGER NOT NULL,

createdAt INTEGER NOT NULL,

UNIQUE(practiceId, dateStr)

);

CREATE INDEX IF NOT EXISTS idx_worship_completions_date

ON worship_completions(dateStr);

CREATE INDEX IF NOT EXISTS idx_worship_completions_practice

ON worship_completions(practiceId, dateStr);

```

**ستون‌های جدید روی `worship_debts`** (فقط اگر PRAGMA بند ۱۹ نشان داد غایب‌اند):
```

ALTER TABLE worship_debts ADD COLUMN practiceId TEXT;

ALTER TABLE worship_debts ADD COLUMN sourceKind TEXT DEFAULT 'MANUAL';

-- MANUAL | PRAYER_SKIP | MUSTAHAB_SKIP | CYCLE_FAST | RAMADAN_FAST

```

**Backfill (اجباری، داخل همان مهاجرت):**
برای هر ردیف `worship_practices` که `dailyDoneDate IS NOT NULL` و
`dailyDone <> 0`، یک ردیف در `worship_completions` درج کن:
- `resultType = dailyDone = -1 ? 'SKIPPED' : 'DONE'`
- `dateStr = dailyDoneDate` · `countDone = MAX(dailyDone, 1)`
- `id = 'wc_backfill_<practiceId>_<dateStr>'` · `INSERT OR IGNORE`

**Backfill بدهی‌ها:** برای هر `worship_debts` با `autoCreated = 1`، تلاش کن
`practiceId` را از تطبیق `title` با `worship_practices.title` پیدا کنی؛ اگر
دقیقاً یک تطبیق بود مقدار بده، وگرنه `NULL` بگذار. تعداد تطبیق‌یافته و
تطبیق‌نیافته را در گزارش بنویس.

⚠️ کل مهاجرت داخل `try/catch` با `debugPrint` که **فقط تعداد** ردیف‌های
پردازش‌شده را چاپ کند، نه محتوای ردیف‌ها.

### ▣ T2 — `WorshipCompletionRepository` (فایل جدید)

**فایل:** `lib/features/worship/logic/worship_completion_repository.dart`

تنها نویسندهٔ مجاز `worship_completions`. API دقیق:

```

class WorshipCompletionRepository {

static final instance = WorshipCompletionRepository._();

/// وضعیت یک تاریخ برای مجموعه‌ای از practiceId. کلید: practiceId

Future<Map<String, WorshipDayStatus>> statusForDate(String dateStr,

{List<String>? practiceIds, DatabaseExecutor? txn});

/// وضعیت بازهٔ تاریخی — برای نمای هفته/ماه تقویم، یک کوئری واحد.

Future<Map<String, Map<String, WorshipDayStatus>>> statusForRange(

String fromDateStr, String toDateStr);

/// ثبت انجام. idempotent: UNIQUE(practiceId, dateStr) با

/// ConflictAlgorithm.replace. `dailyDone`/`dailyDoneDate` را در همان

/// تراکنش هم‌گام می‌کند. undoToken برمی‌گرداند.

Future<String> logDone({

required String practiceId, required String dateStr,

required String practiceType, int countDone = 1, int? countTarget,

});

Future<String> logSkip({

required String practiceId, required String dateStr,

required String practiceType, String? reason,

});

/// حذف ردیف و بازگرداندن dailyDone به وضعیت قبلی.

Future<bool> undo(String recordId);

/// تعداد روزهای متوالی DONE تا dateStr. برای آمار پایبندی.

Future<int> streakFor(String practiceId, {required String upToDateStr});

}

class WorshipDayStatus {

final String recordId;

final String resultType;   // DONE|SKIPPED|PARTIAL|QADA_ADDED

final int countDone;

final int? countTarget;

bool get isDone => resultType == 'DONE';

bool get isSkipped => resultType == 'SKIPPED';

}

```

**الزام:** `logDone` و `logSkip` هر دو در پایان `DayAgendaService.invalidateDate(dateStr)`
را صدا بزنند و `RitmoEventBus().fire(RitmoEvent(type: 'WorshipUpdated', ...))`.
```
