## تشخیص ریشه‌ای (تأییدشده روی کد)

`RoutineNiyyahSheet` **سالم است**. دکمه‌هایش درست عمل می‌کنند:

```

onPressed: () {

RitmoHaptics.confirm();

Navigator.pop(context);

widget.onStartTimer(selectedMode);

}

```

اما `ActionRouter` آن را با کال‌بک‌های **خالی** باز می‌کند:

```

[RoutineNiyyahSheet.show](http://RoutineNiyyahSheet.show)(

context: context,

routine: routine,

onStartTimer: (selectedMode) async {},   // 🔴 تابع خالی

onCompleteInstantly: (modeStr, duration) async {

await CompletionGateway.instance.submit(...);   // ✅ ثبت می‌کند

// 🔴 ولی نه invalidate، نه توست، نه بررسی نتیجه

},

onSnooze: () {},        // 🔴 خالی

onEdit: () {},          // 🔴 خالی

onViewDetails: () {},   // 🔴 خالی

);

```

`ActionRouter` **تنها نقطهٔ ورود تعامل تایم‌لاین** است. تا وقتی این فایل ناقص است، کل تقویم غیرتعاملی به نظر می‌رسد.

## بخش ۱ — زیرساخت مشترک

### T1 — `lib/core/domain/agenda/action_feedback.dart` (فایل جدید، کوچک)

هر عمل موفق در روتر باید **دقیقاً یک** بار این را صدا بزند:

```

class ActionFeedback {

ActionFeedback._();

/// بازخورد یکسان برای همهٔ دامنه‌ها: هپتیک + توست + ابطال کش

static void success(

BuildContext context, {

required String message,

required String dateStr,

String? undoToken,

VoidCallback? onUndo,

}) {

RitmoHaptics.success();

DayAgendaService.instance.invalidateDate(dateStr);

if (!context.mounted) return;

[RitmoToast.show](http://RitmoToast.show)(context, message: message, action: onUndo == null ? null : ...);

}

static void failure(BuildContext context, {required String message}) {

RitmoHaptics.warning();

if (!context.mounted) return;

[RitmoToast.show](http://RitmoToast.show)(context, message: message, isError: true);

}

}

```

**قواعد:**
- `context.mounted` **قبل از هر استفاده از context پس از `await`** بررسی شود. این الان هیچ‌جای روتر رعایت نمی‌شود و منبع کرش خاموش است.
- اگر `undoToken` غیرنull بود، توست دکمهٔ «بازگردانی» با پنجرهٔ ۵ ثانیه نشان دهد که `CompletionGateway.instance.undo(undoToken)` را صدا می‌زند.

### T2 — همهٔ خروجی‌های گیت‌وی بررسی شوند 🔴

الان خروجی `submit()` **دور ریخته می‌شود**. اگر گیت‌وی شکست بخورد، کاربر هیچ نمی‌فهمد.

الگوی اجباری در هر شاخه:

```

final outcome = await CompletionGateway.instance.submit(request);

if (!context.mounted) return;

if (outcome.isSuccess) {

ActionFeedback.success(context, message: '...', dateStr: item.dateStr, undoToken: outcome.undoToken);

} else {

ActionFeedback.failure(context, message: outcome.errorMessage ?? 'ثبت انجام نشد');

}

```

## بخش ۲ — رفع شاخهٔ روتین

### T3 — **B1: `onStartTimer` خالی است** 🔴

```

onStartTimer: (selectedMode) async {

final minutes = _minutesForMode(routine, selectedMode);

if (minutes <= 0) {

ActionFeedback.failure(context, message: 'مدت زمانی برای این حالت تعریف نشده است');

return;

}

await RitmoTimerService.instance.startTimer(

id: 'routine_${[routine.id](http://routine.id)}',   // شناسهٔ پایدار؛ شروع دوباره جایگزین می‌شود نه تکرار

domain: 'routine',

itemId: [routine.id](http://routine.id),

mode: selectedMode,

durationMinutes: minutes,

);

if (!context.mounted) return;

await _showActiveTimerOverlay(context, routine: routine, completionMode: selectedMode, dateStr: item.dateStr);

},

```

**`_minutesForMode`** — یک هلپر خصوصی در همین فایل، دقیقاً هم‌راستا با منطق خود شیت:
```

FULL    → currentTargetMinutes > 0 ? currentTargetMinutes : (targetDurationMinutes ?? 30)

LIGHT   → lightDurationMinutes ?? 20

MINIMAL → minimalDurationMinutes ?? 10

```
خروجی حتماً از `DurationBounds.sanitize()` عبور کند.

**`_showActiveTimerOverlay`** باید **دقیقاً همان مسیری** را برود که `now_dashboard_screen` می‌رود (خروجی `P0-4`).
⛔ **منطق تایمر را بازنویسی نکن.** اگر `now_dashboard` تابع قابل استفادهٔ مجدد دارد، همان را استخراج کن به یک هلپر مشترک و هر دو از آن استفاده کنند. اگر ندارد، هلپر جدید بساز و `now_dashboard` را هم به آن مهاجرت بده.

پس از پایان تایمر (`onFinished`) → `ActionFeedback.success` + `invalidateDate`.

### T4 — **B2: `onSnooze` خالی است** 🔴

```

onSnooze: () async {

final verdict = await SnoozePolicy.evaluate(itemId: [routine.id](http://routine.id), domain: 'routine', dateStr: item.dateStr);

if (!context.mounted) return;

switch (verdict) {

case SnoozeVerdict.allowed:

case SnoozeVerdict.lastCall:

await RoutineActions.snoozeRoutine(

context: context, routineId: [routine.id](http://routine.id), dateStr: item.dateStr,

minutes: await _snoozeMinutesFromSettings(),   // کلید 'snooze_minutes'، پیش‌فرض ۱۰

onDone: () => DayAgendaService.instance.invalidateDate(item.dateStr),

);

if (verdict == SnoozeVerdict.lastCall && context.mounted) {

ActionFeedback.failure(context, message: 'این آخرین تعویق ممکن برای امروز است');

}

case SnoozeVerdict.exhausted:

await _showExitOptionsSheet(context, routine: routine, dateStr: item.dateStr);

case SnoozeVerdict.blockedMedical:

ActionFeedback.failure(context, message: 'تعویق برای موارد دارویی مجاز نیست');

case SnoozeVerdict.blockedMidnight:

ActionFeedback.failure(context, message: 'زمان امروز به پایان رسیده است');

}

},

```

🔴 **بن‌بست شناخته‌شده:** جایی در کد پس از سه تعویق `throw Exception('حداکثر تعداد تعویق (۳ بار) ...')` زده می‌شود. **این `throw` باید حذف شود** و جایش `SnoozeVerdict.exhausted` برگردد. پرتاب استثنا در مسیر UI یعنی دکمه بی‌صدا شکست می‌خورد.

اگر `SnoozePolicy` هنوز وجود ندارد (خروجی `P0-7` خالی)، یک نسخهٔ حداقلی بساز که فقط `deferCount` را با `snooze_max_defer_count` (پیش‌فرض `'3'`) مقایسه کند. ⛔ نسخهٔ کامل ۰۲۵ را اینجا پیاده نکن.

**`_showExitOptionsSheet`** — یک `showModalBottomSheet` سادهٔ سه‌گزینه‌ای، **بدون فایل جدید**، داخل همین فایل:
- «همین حالا نسخهٔ حداقلی را انجام بده» → `submit` با `MINIMAL`
- «به فردا منتقل کن» → `SkipOccurrenceCommand` با دلیل «موکول شد»
- «امروز نمی‌توانم» → انتخاب از شش دلیل ثابت + ثبت رد

### T9 — **B7: دو مسیر موازی ثبت روتین**

`RoutineActions.completeRoutine` از `RitmoExecutionKernel` + `CompleteOccurrenceCommand` استفاده می‌کند، ولی `ActionRouter` از `CompletionGateway` — **دو مسیر متفاوت با رفتار متفاوت** (اولی توست دارد و کامند برگشت‌پذیر می‌سازد، دومی نه).

**رفع در این پرامپت:** بدنهٔ `RoutineActions.completeRoutine` طوری بازنویسی شود که **داخلاً `CompletionGateway.instance.submit` را صدا بزند** و توست فعلی‌اش را حفظ کند. امضای عمومی‌اش **تغییر نکند** تا هفت صداکنندهٔ دیگر نشکنند.
در گزارش بنویس کدام صداکننده‌ها بررسی شدند و هیچ‌کدام نشکست.

## بخش ۳ — بقیهٔ شاخه‌های روتر

### T10 — **B8: دوره، عبادت، گام هدف، دارو بی‌صدا ثبت می‌شوند** 🔴

الان کاربر روی «نماز ظهر» ضربه می‌زند و **بدون هیچ تأیید یا بازخوردی** ثبت انجام می‌خورد. هم غافلگیرکننده است و هم برای عبادت از نظر کاربر ناخوشایند.

برای هر چهار دامنه، یک **شیت تأیید سبک مشترک** داخل همین فایل (نه فایل جدید):

```

┌──────────────────────────────┐

│        نماز ظهر               │

│   امروز، ساعت ۱۳:۱۵          │

│                              │

│   [ ثبت انجام ]  [ تعویق ]    │

│         [ انصراف ]            │

└──────────────────────────────┘

```

- عنوان و ساعت از `AgendaItem`
- «ثبت انجام» → `submit` مربوطه + `ActionFeedback.success`
- «تعویق» فقط برای دامنه‌هایی که مجازند؛ برای دارو مخفی شود
- تأیید نتیجه دقیقاً طبق T2

### T11 — **B9: `KonkurStudySheet` همیشه خالی** 🔴

KonkurStudySheet(subjects: const [], topics: const [], onSaved: () {})

اگر ماژول کنکور خاموش است، اصلاً شیت باز نشود و پیام «ماژول کنکور غیرفعال است» نشان داده شود.

### T13 — **B11: ناهماهنگی نام دامنهٔ دارو** 🔴

`AgendaDomain.medicine` است ولی `CompletionGateway` رشتهٔ `'medication'` می‌فرستد. هر مصرف‌کنندهٔ پایین‌دستی که روی رشته `switch` می‌کند، خاموش شکست می‌خورد.

**رفع:** یکسان‌سازی روی `'medicine'` در کل مسیر. همهٔ نقاط `P0-12` اصلاح شوند. اگر جایی مقدار در دیتابیس ذخیره شده، در خواندن هر دو مقدار پذیرفته شود (سازگاری عقب‌رو) ولی نوشتن فقط `'medicine'` باشد.

### T15 — امضای `open` اصلاح شود

```

```
شاخهٔ روتین الان `RoutineNiyyahSheet.show` (که `void` است) را صدا می‌زند و بلافاصله `break` می‌کند — یعنی `await` صداکننده **قبل از بستن شیت برمی‌گردد**.
