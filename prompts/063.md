## ۱. هفت قانون آهنین

۱. **هر تسک یک شمارهٔ ثابت دارد (T1 تا T36).** گزارش باید دقیقاً ۳۶ ردیف تسک داشته باشد. نه ۳۵، نه ۳۷.
۲. **هیچ تسکی را رد نکن.** اگر نتوانستی، در همان ردیف بنویس «انجام نشد» به‌علاوهٔ پیام خطای واقعی. حذف ردیف = شکست کل پرامپت.
۳. **هر ردیف گزارش باید مسیر فایل و شمارهٔ خط واقعی داشته باشد.** ردیف بدون شمارهٔ خط پذیرفته نیست.
۴. **دو نقطهٔ توقف اجباری** (بعد از فاز ۱ و فاز ۳). در هر نقطه بایست، خروجی دستورهای همان بخش را چاپ کن، بعد ادامه بده.
۵. **تست را قبل از کد بنویس** برای هر تسکی که تست دارد.
۶. **مقایسه با Microsoft To Do فقط رفتاری است.** هیچ فایل صوتی، آیکن، رشتهٔ متنی یا کد دی‌کامپایل‌شده از آن اپ وارد این مخزن نشود.
۷. **واژه‌های ممنوع در گزارش:** «در آینده»، «TODO»، «فعلاً»، «تا حدی»، «تقریباً»، «آماده‌سازی شد»، «زیرساخت اضافه شد»، «باید بررسی شود»، «در نظر گرفته شد». وجود هر کدام = گزارش مردود.

```dart
import 'package:ritmo/core/database/migration/migration_interface.dart';

class MigrationV78TaskUpgrade extends Migration {
  @override
  int get version => 78;

  @override
  Future<void> up(Database db) async {
    final nowMs = DateTime.now().millisecondsSinceEpoch;

    // ۱. ستون‌های تازهٔ simple_tasks — هر کدام داخل try جدا
    for (final sql in [
      "ALTER TABLE simple_tasks ADD COLUMN isImportant INTEGER NOT NULL DEFAULT 0",
      "ALTER TABLE simple_tasks ADD COLUMN importantAt INTEGER",
    ]) {
      try { await db.execute(sql); } catch (_) {}
    }
    await db.execute(
      'CREATE INDEX IF NOT EXISTS idx_simple_tasks_important ON simple_tasks(isImportant);');

    // ۲. جدول زیرگام‌ها
    await db.execute('''
      CREATE TABLE IF NOT EXISTS task_steps (
          id TEXT PRIMARY KEY,
          taskId TEXT NOT NULL,
          title TEXT NOT NULL,
          isCompleted INTEGER NOT NULL DEFAULT 0,
          displayOrder INTEGER NOT NULL DEFAULT 0,
          createdAt INTEGER NOT NULL,
          completedAt INTEGER

    await db.execute(

    // ۳. جدول پیوست‌های محلی

      CREATE TABLE IF NOT EXISTS task_attachments (
          id TEXT PRIMARY KEY,

          fileName TEXT NOT NULL,

    await db.execute(
      'CREATE INDEX IF NOT EXISTS idx_task_attachments_task ON task_attachments(taskId);');

    // ۴. کلیدهای تنظیمات — INSERT OR IGNORE، هرگز replace

  }

  @override
```

## ۴. فاز ۲ — لایهٔ داده

### T8 — گسترش مدل `SimpleTask`

در `lib/features/simple_tasks/domain/simple_task.dart` دو فیلد اضافه کن و در **هر پنج جا** منعکس کن: سازنده، `fromMap`، `toMap`، `copyWith`، و فهرست فیلدهای `final`.

```dart
final bool isImportant;      // پیش‌فرض false
final DateTime? importantAt;
```

در `fromMap`: `isImportant: (m['isImportant'] as int? ?? 0) == 1`
در `toMap`: `'isImportant': isImportant ? 1 : 0`

**هشدار `copyWith`:** الگوی فعلی `x ?? this.x` است، پس نمی‌توان `importantAt` را به `null` برگرداند. برای پاک کردن ستاره از یک پرچم صریح استفاده کن:

```dart
SimpleTask copyWith({..., bool clearImportantAt = false, DateTime? importantAt}) =>
  SimpleTask(..., importantAt: clearImportantAt ? null : (importantAt ?? this.importantAt));
```

### T9 — مدل و مخزن زیرگام

بساز `lib/features/simple_tasks/domain/task_step.dart`:

```dart

  final String taskId;
  final String title;
```

بساز `lib/features/simple_tasks/data/task_step_repository.dart` با سینگلتون `TaskStepRepository.instance` و دقیقاً این متدها:

| متد | امضا | رفتار |
| --- | --- | --- |
| `forTask` | `(String taskId) → List\<TaskStep>` | مرتب بر `displayOrder ASC, createdAt ASC` |
| `add` | `({required String taskId, required String title}) → TaskStep` | `displayOrder = MAX(displayOrder)+1` برای همان `taskId` |
| `setCompleted` | `(String id, {required bool completed})` | `completedAt` را ست/پاک می‌کند |
| `rename` | `(String id, String title)` | `trim()` و اگر خالی بود هیچ کاری نکن |
| `delete` | `(String id)` | — |
| `reorder` | `(String taskId, List\<String> orderedIds)` | `batch`، مثل `SimpleTaskRepository.reorder` |
| `deleteForTask` | `(String taskId)` | — |
| `countsFor` | `(List\<String> taskIds) → Map\<String, (int done, int total)>` | **یک کوئری، نه N کوئری** |

`countsFor` باید دقیقاً این باشد:

```sql
SELECT taskId, COUNT(*) AS total, SUM(isCompleted) AS done
FROM task_steps WHERE taskId IN (...) GROUP BY taskId
```

<aside>

- `d &gt; جمعهٔ همین هفتهٔ شمسی` → `later`

### T35 — دو الگوی تازه

در `lib/core/domain/models.dart`، به `RecurrenceRule` (که امروز فقط `weekdays`، `intervalDays`، `monthDay`، `startDate`، `endDate`، `excludedDates`، `reminderTimes` دارد) دو فیلد nullable اضافه کن:

```dart
final ({int month, int day})? yearlyShamsi;   // مثلاً (month: 1, day: 13) = ۱۳ فروردین
final ({int nth, int weekday})? nthWeekday;   // nth: 1..5 و -1 برای آخرین؛ weekday: 0=شنبه … 6=جمعه
```

در `lib/core/domain/engines/routine_occurrence_generator.dart` منطق تولید را برای این دو حالت اضافه کن.

**هر دو باید شمسی باشند.** «۱۳ فروردین» و «اولین شنبهٔ هر ماه» — نه ۲ آوریل و نه first Monday. از `shamsi_date` استفاده کن. اگر میلادی پیاده کنی، تسک مردود است.

حالت‌های مرزی که باید مدیریت شوند:

- `yearlyShamsi` با `day = 30` در اسفند: در سال غیرکبیسه به ۲۹ اسفند بیفتد، نه به فروردین
- `nthWeekday` با `nth = 5` در ماهی که پنجمین آن روز هفته را ندارد: آن ماه رخدادی تولید نشود
- افق تولید همان ۳۰ روز جلو و `backfillAndGenerateAll` همان `−۳۰..+۳۰` بماند

### T36 — تست‌های سازگاری عقب‌رو

`recurrence_backward_compat_test.dart` — **مهم‌ترین تست این پرامپت.** پنج `RecurrenceRule` واقعی از انواع موجود بساز (روزانه، هفتگی چندروزه، هر `n` روز، ماهانه با `monthDay`، با `excludedDates`)، رخدادهای ۹۰ روز را تولید کن، و تأیید کن فهرست تاریخ‌ها **دقیقاً** با خروجی قبل از این تغییر یکسان است. فهرست مورد انتظار را به‌صورت ثابت در خود تست بنویس.
